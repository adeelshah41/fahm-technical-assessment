1. Objective
Design, build, and deploy an end-to-end, full-stack AI application that processes a mammogram
image and outputs a binary classification: Malignant vs. Benign/Normal, with a confidence
score.
This task evaluates your full-stack engineering agility, ML modeling, cross-platform deployment
skills, and handling of sensitive medical-data structures. It is a representative proxy task — it
mirrors the kind of problem you'd work on at FAHM, not our actual product pipeline.
Estimated effort: a focused 1–2 days. Prioritise a clean, well-documented core
over feature completeness. We would rather see a smaller solution you understand
deeply than a large one you can't explain.
2. Core functional requirements
● Data selection: Choose an established public mammography dataset (e.g.
CBIS-DDSM, MIAS, or INbreast). State your choice and rationale in your report.
● ML model: Train a binary classifier for mammogram scans.
● Backend API: A lightweight, scalable backend handling image ingestion, preprocessing,
model inference, and response delivery.
● Frontend UI: A clean, intuitive web interface where a clinician can upload a
mammogram (DICOM, PNG, or JPEG) and immediately see the classification result and
confidence score.
● Cloud deployment: Deploy the application to a cloud platform. GCP preferred;
free-tier or a temporary deployment is completely fine.

3. Privacy & data-security constraint
Medical data requires strict protection. Your solution should demonstrate built-in privacy
practices. In your documentation, describe how your architecture addresses:
● Data security in transit and at rest
● Anonymisation / de-identification protocols
● Compliance with strict regulatory frameworks (e.g. the Saudi PDPL)
4. Required deliverables
Submit by email with the following:
1. GitHub repository link — clean, production-grade source code, a Dockerfile
(if applicable), and a thorough README.md with step-by-step instructions to build,
configure, and run the system locally.
2. Live application link — a URL to the deployed frontend for
real-time testing.
3. Technical PDF report — concise, covering:
○ Architecture overview (frontend, backend, cloud infra)
○ ML performance metrics: Accuracy, Sensitivity (Recall), Specificity, and the
ROC curve with AUC. Discuss class imbalance and why accuracy alone is
insufficient for a screening task.
○ The data privacy & security framework you used

5. What we value
● Honest, complete metrics (especially sensitivity and AUC — not just accuracy)
● Clear architecture and clean, reproducible code
● Thoughtful privacy/security reasoning
● Clear communication of your trade-offs and what you'd do with more time
